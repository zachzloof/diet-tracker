# Building the native shells (Capacitor)

Decision D1 chose Vue as a PWA now and Capacitor later. Slice 5 scaffolded the `ios/` and
`android/` projects under `apps/web/` so the path exists; nothing in the web app depends on
them, and the PWA from the Railway URL stays the way friends use the app.

## What is in the repo

```
apps/web/capacitor.config.ts   app id, name, web dir, background colours
apps/web/android/              Gradle project generated by `cap add android` (Capacitor 8)
apps/web/ios/                  Xcode project generated by `cap add ios` (Capacitor 8)
```

`@capacitor/core` is a runtime dependency of the web app but is not imported anywhere yet, so
the PWA bundle is unchanged. The CLI and the two platform packages are dev dependencies.

## One-time setup

- Node 24 and pnpm (already required).
- Android: Android Studio (or the command-line SDK) with an API 35 SDK and a JDK 21.
- iOS: a Mac with Xcode 16 or later and CocoaPods (`sudo gem install cocoapods` or Homebrew).
  The `ios/` folder was generated on Windows, so the first `cap sync` on a Mac runs
  `pod install`; that is expected.

## Build and run

```
pnpm --filter @diet-tracker/web build      # dist/
cd apps/web
pnpm exec cap sync                          # copies dist/ into both projects, installs plugins
pnpm exec cap open android                  # Android Studio; run on an emulator or a phone
pnpm exec cap open ios                      # Xcode; pick a simulator or a device and run
```

Repeat `build` and `sync` after every web change. `cap sync` is idempotent.

## The open decision: what the shell loads (D23)

**A. Load the deployed site.** Uncomment `server.url` in `capacitor.config.ts` with the
Railway domain. The shell is a browser pointed at the live app: the session cookie works as
is, updates ship with every push to `main`, and nothing else changes. The cost: Apple can
reject a wrapper with no native functionality (guideline 4.2), and the app is blank without
a connection until the service worker has cached the shell.

**B. Bundle the build.** The default config: `dist/` is copied into the app and served from
`capacitor://localhost` (iOS) or `https://localhost` (Android). The app opens instantly and
offline, and native plugins slot in. The cost: API calls go cross-origin to the Railway
domain, so the API needs CORS for the two local origins and the `SameSite=Lax` cookie will
not be sent. The clean fix is the one D4 anticipated: keep the DB session table, but let a
native client hold the token in secure storage and send it as `Authorization: Bearer`. It is
a contained change in `apps/api/src/auth/session-middleware.ts` (read the bearer header as
an alternative to the cookie) and in `apps/web/src/lib/api.ts` (attach it when running
inside Capacitor, detected with `Capacitor.isNativePlatform()`), plus `VITE_API_ORIGIN` so
the native build knows where the API lives.

Recommendation: B for the store, A for a first TestFlight to friends this month. Both are a
config change away; see docs/DECISIONS.md D23.

## Plugins worth adding first

| Need                              | Plugin                            | Replaces                                       |
| --------------------------------- | --------------------------------- | ---------------------------------------------- |
| Reminders that fire when closed   | `@capacitor/local-notifications`  | the in-tab timer in `stores/reminders.ts`      |
| Save the export to Files / share  | `@capacitor/filesystem` + `share` | the `<a download>` links on Settings           |
| Status bar colour, splash screen  | `@capacitor/status-bar`, `splash-screen` | the `theme-color` meta tag              |
| Weight from Apple Health / Health Connect | community `capacitor-health` | manual weigh-ins (an idea after slice 5) |

Each is `pnpm --filter @diet-tracker/web add <plugin>` then `cap sync`, and a small
`if (Capacitor.isNativePlatform())` branch in the store or component that uses it.
