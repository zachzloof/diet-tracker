# Building the native shells (Capacitor)

Decision D1 chose Vue as a PWA now and Capacitor later. Slice 5 scaffolded the `ios/` and
`android/` projects under `apps/web/`; the store preparation on 2026-09-30 made the web app
work inside them (D23 option B). The PWA from the Railway URL stays the way friends use the
app, and nothing below changes how it behaves.

**Not yet built or run on a device.** Everything here typechecks and the API side is tested,
but the first build on a Mac is the first time the native paths execute.

## What is in the repo

```
apps/web/capacitor.config.ts   app id (app.minori.mobile), name, web dir, background colours
apps/web/.env.example          VITE_API_ORIGIN, the one variable the native build needs
apps/web/android/              Gradle project generated by `cap add android` (Capacitor 8)
apps/web/ios/                  Xcode project generated by `cap add ios` (Capacitor 8, Swift PM)
apps/web/src/lib/native.ts     `isNative` and `API_ORIGIN`
apps/web/src/lib/session-token.ts   the session token in the Keychain / Keystore
```

## How the shell differs from the browser app

The shell ships the built web app and serves it from `capacitor://localhost` (iOS) or
`https://localhost` (Android). Everything that differs sits behind `isNative`:

| Concern        | Browser / PWA                          | Native shell                                                                                   |
| -------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| API address    | same origin, `/api/v1`                 | `VITE_API_ORIGIN` + `/api/v1`, cross-origin with CORS                                          |
| Session        | HttpOnly cookie                        | token from login in secure storage, sent as `Authorization: Bearer`                            |
| Reminders      | a timer while the app is open (D22)    | `@capacitor/local-notifications`: the OS fires them daily, app closed or not                   |
| Exports        | a download link                        | fetched, written to the cache, handed to the share sheet (`@capacitor/filesystem`, `share`)    |
| Status bar     | `theme-color` meta tag                 | `@capacitor/status-bar` follows the theme                                                      |
| Service worker | registered, caches the app shell       | not registered; the bundle is already on the device                                            |
| Install hint   | shown in a browser tab                 | never shown                                                                                    |

The plugins are loaded with dynamic imports, so the browser bundle does not carry them.

## One-time setup

- Node 24 and pnpm (already required).
- `cp apps/web/.env.example apps/web/.env.native` and set `VITE_API_ORIGIN` to the deployed
  API's https origin. The native build refuses to run without it.
- Android: Android Studio (or the command-line SDK) with an API 35 SDK and a JDK 21.
- iOS: a Mac with Xcode 16 or later. The project uses Swift Package Manager, so there is no
  `pod install`; Xcode resolves the packages the first time it opens the project.

## Build and run

```
pnpm --filter @diet-tracker/web cap:sync   # vite build --mode native, then cap sync
cd apps/web
pnpm exec cap open ios                     # Xcode: pick your team, a device, and run
pnpm exec cap open android                 # Android Studio; run on an emulator or a phone
```

Repeat `cap:sync` after every web change; it is idempotent. The API must be deployed with
the bearer and CORS support (any deploy from 2026-09-30 on) before the shell can sign in.

## First run on a device: what to check

1. Register or sign in, close the app from the switcher, open it again: still signed in.
2. The header clears the notch and the tab bar clears the home indicator, with no double
   gap. If there is one, `ios.contentInset` in `capacitor.config.ts` is the setting.
3. Settings, Reminders: switching it on asks for notification permission; set a time two
   minutes ahead, close the app, and the notification arrives.
4. Settings, Your data: each export opens the share sheet with a file.
5. Airplane mode: the app opens and shows the last known day.
6. Light and dark theme: the status bar text is readable in both.

## Releasing

Bump `MARKETING_VERSION` (what people see) and `CURRENT_PROJECT_VERSION` (must increase
with every upload) in Xcode, and `versionName` / `versionCode` in
`apps/web/android/app/build.gradle`. Archive in Xcode (Product, Archive) and upload to App
Store Connect. `docs/APP-STORE.md` lists what the listing and the review need.

## Plugins that could come later

| Need                                      | Plugin                       |
| ----------------------------------------- | ---------------------------- |
| Weight from Apple Health / Health Connect | community `capacitor-health` |
| Haptics on logging                        | `@capacitor/haptics`         |
| Barcode or photo logging                  | `@capacitor/camera`          |

Each is `pnpm --filter @diet-tracker/web add <plugin>` then `cap:sync`, and a small
`if (isNative)` branch in the store or component that uses it. Anything that asks for a new
permission also needs its usage string in `Info.plist` and a line in the privacy policy.
