# Mobile UI

## Intent
It has to look like something people would pay for, and it has to be usable one-handed on a phone while holding a fork. Bold numbers, calm surfaces, one accent, instant feedback. Dark is the design lead and the default for a fresh install; light must be just as finished because Settings offers it (Dark / Light / System).

## App shell
- `100dvh` layout, content scrolls, header and bottom bar fixed. Padding uses `env(safe-area-inset-*)` so the iPhone home indicator and notch never cover anything. `viewport-fit=cover` in the meta tag.
- Two halves (D38): **Food** and **Gym**, switched by `ModeToggle`, a two-segment pill centred in the header of every root screen (never on a pushed screen, which has a back button instead). `useAppMode` gives the current half; routes declare theirs with `meta.mode`. The header is a three-column grid (title, switch, actions), so a root screen's header-right slot holds at most one icon button; anything wider (the day and week arrows) goes into the body as a `DayStepper` row directly under the header. A pushed screen may fill the middle with its own `PillToggle` through `AppShell`'s `header-centre` slot (the session's Last / Best, D39): the title then keeps its words up to 10 rem and the pill nudges rather than clips, and whatever sits at the right must be an icon under 400 px wide (the session's save status hides its words there with `max-[399px]:sr-only`).
- Bottom tab bar, five slots per half. Food: **Today**, **Meals**, **Log**, **Week**, **You**. Gym: **Today**, **Workouts**, **Log**, **Week**, **You**. You is the same screen in both. Log, in the centre, is a raised circular "+" that opens the quick-add sheet (food) or starts a session (gym) from anywhere; that is the app's primary action and it must be reachable by a thumb. The sheet has four ways in (Describe, Meals, My foods, Manual), each with a one-line description under the title. A tab stays lit on the pushed screens that belong to it (the meal editor under Meals, a session under Workouts, Lifts under the gym's Week). Five is the ceiling: anything else a person manages (My foods, Progress, Settings) is a pushed screen under You.
- A screen with its own bottom bar (the coach's composer) passes `hide-tabs` and fills `AppShell`'s `footer` slot: the slot is fixed to the bottom in place of the tab bar, pads itself by the safe area or the visual-viewport keyboard inset (`useKeyboardInset`, as the sheets do), and the main column pads its bottom to match so the last line can scroll above it. The shell reads `$slots.footer` in the template, so a footer that appears later (after consent) is still picked up. The coach is reached from a sparkles `IconButton` in the header-right slot of Today and Week in both halves and a row under You; it is a pushed screen (back to the half's Today) with the clock icon on the right for its chat list, which carries a Notes row at the top to `/coach/notes` (a list with a bin per note and a confirm sheet, like the chat list).
- A screen whose running totals matter while you scroll pins them under the header (the session's tally, `features/training/WorkoutTally.vue`): the first thing in `main`, `sticky` at `top: calc(3.5rem + env(safe-area-inset-top))` with `z-10` (the header is `z-20`), in a `-mx-4 px-4 py-2 bg-bg/90 backdrop-blur` band like the header so content slides under it, holding one card of three centred stats (number `text-xl` bold, label `text-xs` muted). A clock in it is `role="timer"`, never `aria-live`, so a screen reader is not told every second.
- Screens are single-column, max width 480 px centred on larger screens so desktop is just a wide phone.
- Modal actions come up as bottom sheets (Reka UI Dialog styled as a sheet), never centred modals. Sheets have a drag handle, a visible close, and never trap focus without an escape.
- Page transitions: none between tabs; a slide-in for pushed detail screens.

## Tokens (`apps/web/src/styles/tokens.css`, mapped into Tailwind v4 `@theme`)
- Surfaces: `--bg` (dark `#0c0f14`, light `#f7f8fa`), `--surface`, `--surface-2`, `--border`, `--fg`, `--fg-muted`.
- Accent: one brand hue used sparingly for the primary action and the energy ring. Default a saturated lime-green (`#7cf29a` dark / `#15803d` light, the light value chosen for 5:1 on white so button labels pass contrast); revisit at naming time.
- Semantic macro colours, fixed everywhere: protein `#60a5fa` (blue), carbs `#fbbf24` (amber), fat `#f472b6` (pink), fibre `#34d399` (teal-green), water `#38bdf8` (sky).
- Status: `met` green, `close` amber, `short` neutral grey with an outline, `over` coral red (`#f0564f` dark, `#dc2626` light because it is also error text). `--danger` follows the same rule (`#e5484d` dark, `#c53030` light). Status colours never double as macro colours.
- Type: system font stack (`-apple-system, Inter, Segoe UI, Roboto`) with `font-variant-numeric: tabular-nums` on every number. Scale: 12 / 14 / 16 / 20 / 28 / 44 (hero). Body 16 px minimum, which also stops iOS zooming inputs.
- Radius 16 px cards, 12 px controls, full for chips. Shadows only in light mode; dark mode uses surface steps.
- Spacing on a 4 px grid; screen gutter 16 px.
- Dark is the `:root` base; light is `:root[data-theme='light']`. The CSS never reads `prefers-color-scheme`: `stores/ui.ts` (and an inline script in `index.html`, before first paint) resolve the saved preference, default `dark`, to `data-theme="dark|light"`.

## Components (`apps/web/src/components/ui/`)
Build these once in slice 1 and reuse: `AppShell`, `TabBar`, `Sheet`, `Button` (primary, secondary, ghost, destructive; 48 px tall), `IconButton`, `Card`, `Input` (with label, helper, error, right-slot unit), `NumberField` (`inputmode="decimal"`, unit suffix, stepper), `Select` (native on mobile, it is better than any custom one), `SegmentedControl`, `PillToggle` (the 36 px header pill; `ModeToggle` is one), `DayStepper` (`atEnd` where the forward arrow may pass the present, as Today's does for one day), `Toggle`, `Chip`, `ProgressBar` (macro bars; `planned` adds the lighter tone), `Ring` (SVG, animated stroke; `planned` likewise), `StatTile`, `Skeleton`, `EmptyState`, `Toast`, `OfflineBanner`, `LineChart` (single series with an optional secondary trend line, a target hairline, `domain="auto"` for series that should not start at zero, `labelEvery` for dense axes), `ErrorScreen` (the error boundary's fallback, mounted from `App.vue`).
Feature screens live in `apps/web/src/features/<feature>/` and compose these; they don't write raw Tailwind for things a component covers. The chat pieces (`CoachBubble`, `CoachComposer` under `features/coach/`) are the one feature-owned pair: the person's bubble right in the accent tint, the coach's left on a surface with the lines it looked at above the text, a pulsing status line while a tool runs, three bouncing dots before the first token, the failure copy in an `over`-bordered bubble with Try again; the composer is one growing line with a round accent send button, `enterkeyhint="send"`, disabled offline with "The coach needs a connection." under it. The coach's cards (`features/coach/cards/`, slice 11b) share `CardFrame`: a full-width `section` under the bubble with an accent-tinted border while drafted (plain and dimmed once dismissed), an accent icon and a short heading, the body, then the confirm button (named for the action: "Add to breakfast", "Apply", "Start", "Save to meals", "Remember") beside a ghost Dismiss, replaced by a `met` chip ("Logged", "Applied", "Started", "Saved", "Remembered") or a neutral "Dismissed" chip once acted on; "(offline)" on a confirm that needs the network. Each body reuses what the app already draws: the estimate card is `EstimateReview` itself (with `hide-edit`); the target card shows before struck through → after in the hero size with the dependants as label/number rows and the floor line under a shield; the workout card lists set rows "1 · 77.5 kg × 5 · 75 kg × 5" with last time's set greyed on the right; the meal card is the ingredient list with the P/C/F strip. The daily brief (`features/coach/BriefCard.vue`, slice 11c) is one accent-tinted full-width button on Today in both halves, under the status line and only on today: sparkles at the left, the sentence at body size, a chevron at the right; a one-line skeleton while it loads, nothing before AI consent or on an error, disabled offline. The owner's AI costs screen (`features/you/CostsScreen.vue`, pushed from You, only for the owner) is four `StatTile`s in a two-column grid then two list cards (By purpose, By person with each person's purposes as small rows).

## Screen states (every screen has all of them)
Loading = skeletons in the layout's shape, never a spinner in the middle. Empty = one sentence and one primary action. Error = what happened in plain words and a retry. Offline = a slim banner plus whatever cached data exists, with actions that need the network disabled and labelled.

## Forms for thumbs
- One question per screen in onboarding, big touch targets, the primary button pinned above the keyboard.
- Numeric entry uses `NumberField` with the unit visible and sensible steps (0.5 kg, 1 cm, 5 g).
- Native `<select>` and `<input type="date">` on mobile; they open the OS pickers people already know.
- Autofocus the first field on desktop only; on mobile the keyboard jumping up on load is disorienting.
- Validation inline, on blur, in words ("Weight should be between 30 and 300 kg").
- Never require a field whose label needs explaining; add helper text or drop the field.

## Motion
150 to 250 ms, ease-out. Rings and bars animate from 0 to value on first paint of a screen and from old to new value on updates. Sheets are the one exception to the range: they rise in 420 ms on a soft-landing curve with their content settling a beat later, and drop out in 240 ms (`animate-sheet-in`, `animate-sheet-out`, `animate-sheet-body` in `main.css`). A sheet whose content changes height as you use it (quick add) takes `size="tall"` so it holds one height just under the status bar; `Sheet` pads itself above the on-screen keyboard. Respect `prefers-reduced-motion` by switching to instant. No bounce, no confetti except one tasteful moment when a day is met for the first time.

## Planned food (D43)
Food not eaten yet has no meal of the day, so Planned sits with the four meals in `MealDayPicker`, whose `v-model:planned` every way of logging binds; a future day narrows the options to Planned alone and forces it on, and says why under the chips. Confirm labels and toasts come from `features/log/log-slot.ts`. `features/log/PlannedList.vue` is one card above the meals: a tick in a 56 px column beside the row button (two siblings, never a button in a button), muted kcal because the number is not in the day yet, the calendar icon and no tick on a plan-only day, the clock on a queued row. The tick uses `mutateAsync`, because the list unmounts with its last row and would drop a per-call callback. Numbers are always eaten; a plan only draws the lighter tone (the bar's colour at 35%) from the eaten amount on, plus the "· 640 planned" caption under the ring with a dot as the legend. Today on a plan-only day has a "Plan only" chip in place of the day status and no water, weigh-in, brief, food groups or vitamins, and passes `log-day` to `AppShell` so the centre + plans that day. Anything on Today that adds up reads `foodEntries`, which is eaten only.

## Charts
Rings and bars are small hand-written SVG components with tokens for colour; no chart library for those. Line charts (weight trend in slice 5) use a tiny custom SVG too unless it gets painful, then `unovis` or `chart.js` via a decision. Before drawing any chart, load the `dataviz` skill for form and colour rules, then map its palette onto the tokens above rather than introducing new colours.

History screens (Progress, the Workouts list, a lift's page) put a `SegmentedControl` of ranges at the top, taken from `HISTORY_RANGES` in `apps/web/src/lib/ranges.ts` (4 weeks, 3 months, 6 months, 1 year; the longest is `MAX_RANGE_DAYS`, the year the app keeps). A read longer than three months passes `meta: { mirror: false }` so it stays out of the offline mirror. `LineChart` decides density itself: when points sit closer than one marker on average it draws one joined line, marks only the latest, highlighted and touched points, and snaps the readout to the nearest point with a value, so no screen passes a flag for it.

## Accessibility baseline
Touch targets 44 px minimum, colour never the only signal (status has an icon or text), contrast AA in both themes, every icon-only button has an `aria-label`, focus visible for keyboard users on desktop, `aria-live` on the quick-add result. A button with visible text must not get an `aria-label` that starts differently (Lighthouse "label-content-name-mismatch"); add an `sr-only` span for the extra context instead. Every page has one `<main>` (the auth and legal layouts included).

## Offline (slice 5)
Offline is a state of every screen that writes: cached data beats an error, a paused query with nothing cached shows an offline card with a retry, and writes that can be queued say "(offline)" on the button rather than disabling it. The AI path is the one action that stays disabled offline. The mirror and the queue live in `lib/query-client.ts` and `stores/queue.ts` (D21). A mutation with its own offline path needs `networkMode: 'always'`, or TanStack pauses it while offline and the path never runs; a mutation that is simply disabled offline leaves the default.

## Checklist before calling a screen done
Looks right at 360, 390 and 430 wide; dark and light; all four states; keyboard open doesn't hide the primary action; nothing overflows horizontally; numbers are tabular; safe areas respected on a notched device simulation.
